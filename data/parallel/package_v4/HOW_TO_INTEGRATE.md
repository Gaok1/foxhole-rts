PowerShell: `(Get-FileHash mod\FoxholeRTS\Scripts\main.lua -Algorithm SHA256).Hash` (uppercase). The file is consistently
CRLF (`test_stack_v4.py` step 00 checks it); do not pass it through an editor that normalizes line endings.

**Option B: patch chain** (reproduced by me on a copy, with `patch --binary`; the four SHAs match). Only if you want to
audit step by step; it is equivalent to A:

and do not match the CRLF main). Do not apply BASES before COLETA nor collection before the v2 stack.

## 6. Permanent battery after integration

Once the real main is v4, the `test_*.py` of the folders that do `build(main)` (apply their own patch over the main)
can no longer run (the anchors were already consumed) and those that call `harness_*` with the file on disk start testing
the old candidate, not the main. Two techniques already proven in the repository solve this without editing the original tests:

- **`BASES_V4_FILE`**: an environment variable that `forward_bases/stage2/harness_bases.py` reads to swap the target file.
  Point it at the real main and the BASES and COLETA suites run without editing.
- **`__CANDIDATE`**: an in-memory copy of the test with the line that obtains the candidate swapped (`exec` with the real main's
  text). This is what `test_stack_v4.py` does in steps 05, 06, 06b, 06c, 07, 08 and 09.

`data/parallel/package_v4/post_integration_battery.py` combines both (reads the real main; writes nothing to disk, only stdout;
`--main FILE` points at another file for a rehearsal; runs in ~30 s). There is one detail that cannot be worked around another way:
`test_elogi`, `test_bmat_caminhao` and `test_persistencia_v2` build **alternative** stacks ("without AI", "without collection") by applying
the `build_*.py` to the **previous** main and read `mod/FoxholeRTS/Scripts/main.lua` directly in the test's text. After integration
that file is already v4 and the anchors no longer exist (reproduced: 5 `âncora não única` failures). That is why this folder keeps a

## 9. Save compatibility

- **v4 opens v3 and v2 saves**: missing sections are accepted (`fwd` optional; missing `elogi` → "o save não traz a cadeia
  inimiga" and the chain restarts from the scenario stock, with the warning `CADEIA INIMIGA REINICIADA (…)`).
- **The reverse does not hold**: v3 refuses a save with `fwd` ("campo desconhecido: fwd"); v3 and v2 refuse a save with workers
  (unknown `role="worker"`) and with a 2-truck deployment (they require 3). A v4 save **without** bases and **without** workers
  is read by v3.
- Schema: `CFG.PERSIST.version = 2`, `infraVersion = 1`, `enemyVersion = 1`, `fwdVersion = 1`.
- An invalid `elogi`, of a future version or without logistics, discards **only the section** (the enemy chain restarts); any other
  invalid field refuses everything and keeps the current match and the file ("Continuar recusado (partida atual e save preservados)").
- Writing: checked `.tmp` → the previous becomes `.bak` (or `.corrupt` if invalid) → `.tmp` becomes the save. An incomplete continue
  suspends the autosave ("INCOMPLETA … autosave suspenso"). A pending forward base order is **not** saved.
- There is no migration of the deployment wallet between `1100` and `1000`: the save keeps what was paid (`spent`, `built`).
